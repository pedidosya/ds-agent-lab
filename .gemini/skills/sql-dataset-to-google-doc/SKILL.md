# SQL Dataset to Google Doc Skill

Use this skill when the user provides a SQL file path and wants dataset documentation created as a Google Doc.

This skill always follows the same workflow:

SQL file → structured JSON → rendered TXT → Google Doc

The user only needs to provide the dataset-specific inputs.

---

# Expected inputs

The user may provide:

- `SQL_FILE_PATH`: path to the SQL file.
- `MODEL_GOAL`: model objective.
- `DOC_TITLE`: Google Doc title.
- `DRIVE_FOLDER_NAME`: Google Drive folder where the document should be moved.
- `OUTPUT_BASENAME`: base name for generated local documentation files.
- `AUDIENCE`: optional target audience.
- `LANGUAGE`: optional documentation language.

If optional inputs are missing:

- Infer the dataset name from the SQL file or final output table.
- Infer the model goal from the SQL, target column, comments, or table name.
- Use a semi-technical data audience.
- Write in English unless another language is requested.
- Generate a concise Google Doc title.
- If `DRIVE_FOLDER_NAME` is missing, create the Google Doc in the default Drive location.
- If `OUTPUT_BASENAME` is missing, infer it from the SQL file name.
  Example: `dataset/dataset_p_open.sql` → `dataset_p_open_documentation`.

---

# Fixed task

For every execution, the task is always:

1. Read the SQL file.
2. Generate structured dataset documentation.
3. Save the documentation as JSON.
4. Render the JSON into a simple `.txt` file using the skill script.
5. Create a Google Doc.
6. Copy the exact `.txt` content into the Google Doc.
7. Move the Google Doc into the requested Drive folder, if provided.

The user does not need to repeat this task when invoking the skill.

---

# Core instructions

1. Read the SQL file from `SQL_FILE_PATH`.
2. Identify the final output table.
3. Infer the dataset purpose.
4. Infer the final dataset grain.
5. Identify the target column, if present.
6. Identify all relevant source tables.
7. Summarize the main SQL blocks.
8. Document generated features.
9. Document filters, joins, assumptions, and risks.
10. Determine `OUTPUT_BASENAME`.
11. Generate a structured JSON file with the documentation content.
12. Save the JSON file to `docs/[OUTPUT_BASENAME].json`.
13. Render the JSON into simple Google-Doc-friendly text using `scripts/render_doc.py`.
14. Save the text file to `docs/[OUTPUT_BASENAME].txt`.
15. Confirm that `docs/[OUTPUT_BASENAME].txt` exists.
16. Read the exact content from `docs/[OUTPUT_BASENAME].txt`.
17. Create a Google Doc using Google Workspace MCP.
18. Write the exact `.txt` content into the Google Doc without changing, rewriting, summarizing, improving, or adding anything.
19. If `DRIVE_FOLDER_NAME` is provided:
    - Find the folder using Google Drive MCP.
    - Move the created Google Doc into that folder.

Do not modify the SQL file.

---

# Required intermediate files

Before creating the Google Doc, create local documentation files under the `docs/` folder.

If `OUTPUT_BASENAME` is provided, use it.

Example:

- `OUTPUT_BASENAME`: `p_open_dataset_documentation`
- JSON file: `docs/p_open_dataset_documentation.json`
- Text file: `docs/p_open_dataset_documentation.txt`

If `OUTPUT_BASENAME` is not provided, infer it from `SQL_FILE_PATH`.

Example:

- `SQL_FILE_PATH`: `dataset/dataset_p_open.sql`
- inferred `OUTPUT_BASENAME`: `dataset_p_open_documentation`
- JSON file: `docs/dataset_p_open_documentation.json`
- Text file: `docs/dataset_p_open_documentation.txt`

The JSON file is the source of truth.

The text file must be generated by running:

```bash
python .gemini/skills/sql-dataset-to-google-doc/scripts/render_doc.py docs/[OUTPUT_BASENAME].json docs/[OUTPUT_BASENAME].txt
